## 개요

**Offline wearable lifelogging.** 하루를 기록하는 목걸이형 웨어러블이다.

목걸이가 대화를 녹음해 쌓아두면, 폰이 주기적으로 가져가서 텍스트로 바꾸고 위치·시각과 함께 타임라인으로 정리한다.

### 왜 만들었나

- 하루에 나눈 대화, 떠오른 생각, 들은 정보는 대부분 기록되지 않고 사라진다.
- 폰 녹음 앱은 매번 꺼내서 켜야 하고, 하루 종일 켜두면 폰 배터리와 저장 공간이 버티지 못한다.
- 시중 AI 펜던트는 클라우드 구독에 의존하고, 내 음성이 어디서 어떻게 처리되는지 통제하기 어렵다.

그래서 목표는 **신경 쓰지 않아도 하루가 기록되고, 기록은 내 폰에만 남는 것**이다. 1차 사용자는 나 자신 한 명이다.

### 핵심 원칙: 기록은 밖으로 나가지 않는다

음성·위치·텍스트는 기기와 내 폰에만 존재한다. STT는 폰 안에서(온디바이스) 하고, 클라우드 STT·네트워크 지오코딩은 쓰지 않는다. Android 자동 백업과 기기 간 이전도 꺼서 녹음과 DB가 Google Drive로 올라가지 않게 했다. 예외는 사용자가 직접 내보낸 파일뿐이다.

## 사용 기술

| 영역 | 기술 |
|---|---|
| 하드웨어 | Seeed XIAO nRF54L15 Sense, W25Q128 16MB SPI 플래시, 250mAh LiPo, 버튼 1개 |
| 펌웨어 | Zephyr RTOS (nRF Connect SDK v3.4.1), LittleFS, libopus 1.5.2 (fixed-point) |
| 앱 | Android, Kotlin, Jetpack Compose, Room, WorkManager, CompanionDeviceManager |
| 도구 | Python (프로토콜 레퍼런스 `owlproto.py`, PC 동기화 `sync.py`, 가짜 기기, Google Bumble) |
| 케이스 | OpenSCAD 파라메트릭 모델 → 3D 프린팅 |
| CI | GitHub Actions (tools / firmware / android, 바뀐 폴더만 검사) |

## 구조

```
목걸이: 마이크 → VAD → Opus → 플래시 ──BLE(폰이 요청)──▶ 폰: 저장 → ACK → STT → 타임라인
                                                          폰 GPS ─────────────┘
```

![목걸이와 폰의 역할 분담: 목걸이는 녹음해 플래시에 쌓고, 폰이 BLE로 가져가 저장·ACK·STT·타임라인을 처리한다](/images/posts/owl/system.svg)
*그림. 목걸이는 녹음해서 쌓기만 하고, 폰이 15분마다 가져가 저장한 뒤 ACK하면 그때 목걸이가 지운다.*

- **기기는 녹음하고 쌓기만 한다.** STT, 위치, 시각 복원은 전부 폰이 한다. nRF54L15로는 온디바이스 STT가 불가능하기 때문이다.
- **실시간 스트리밍은 없다.** 폰이 근처에 있으면 15분마다 연결해서 가져간다(배치 전송). 무선 시간을 줄여 배터리를 아낀다.
- **기기는 GPS가 없다.** 위치는 폰 GPS로 기록한다.
- **기기 시계를 믿지 않는다.** RTC 배터리가 없어서 기기는 `(boot_count, uptime)`만 남기고, 실제 시각 변환은 폰이 한다.

레포는 모노레포다. 펌웨어·앱·도구가 같은 BLE 프로토콜을 공유해서, 프로토콜이 바뀌면 세 곳이 한 커밋에서 같이 바뀌어야 하기 때문이다.

```
protocol/   BLE 프로토콜 명세 — 펌웨어와 앱의 계약서
firmware/   Zephyr 앱 (녹음·VAD·Opus·BLE) + bringup/ 점검 앱
android/    Android 앱 (동기화·타임라인 UI)
tools/      Python 프로토콜 레퍼런스, PC 동기화, 가짜 기기
hardware/   배선, BOM, 케이스
docs/       PRD, 아키텍처, 설계 결정, 로드맵
```

문서는 PRD가 기준(ground truth)이고, "어떻게"는 `decisions.md`와 `protocol/`이 정한다. 설계 결정은 번호를 붙여 계속 쌓았다.

## 구현 내용

### 목걸이 (펌웨어)

- **상시 녹음 + VAD**: 사람 목소리가 나면 조작 없이 녹음하고, 조용한 구간은 저장하지 않는다.
- **Opus 압축 저장**: 16kHz 모노, 16kbps로 시작했다. 16MB 플래시에 음성 약 2시간 분량이 들어간다.
- **유실 없는 보관**: 폰이 ACK하기 전엔 어떤 세그먼트도 지우지 않는다. 플래시가 가득 차면 덮어쓰지 않고 녹음을 멈춘 뒤 LED·이벤트로 알린다.
- **플래시는 LittleFS**: 세그먼트 하나가 파일 하나다. 닳음 분산과 전원 차단 복구를 직접 짜지 않으려고 골랐다.
- **버튼 하나**: 짧게 = 북마크, 2초 = 녹음 끄기/켜기, 5초 = 기기 끄기/켜기(System OFF). 녹음 끄기는 타인 대화 녹음 위험 때문에 폰 없이 바로 할 수 있어야 해서 버튼에 넣었다. 꺼둔 상태는 재부팅해도 유지된다.
- **배터리 보호**: 3.6V 아래면 경고, 3.5V 아래면 System OFF. 보드에 USB 감지 핀이 없어서, 배터리로 꺼진 경우에만 1시간마다 깨어나 전압을 확인하고 충전됐으면 다시 켜진다.

### BLE 프로토콜

- 폰이 당겨가는 **pull 방식**이다. 폰이 목록을 묻고(LIST) 세그먼트를 요청하면(FETCH), 기기가 DATA로 보내고, 폰이 디스크에 저장한 **뒤에** CRC32와 함께 ACK한다.
- 끊기면 offset부터 이어받는다.
- **LE Secure Connections 본딩**: 본딩된 폰과의 암호화 연결에서만 명령을 받는다. 새 페어링은 본딩된 폰이 없거나 기기를 켠 뒤 120초 안에만 된다. 자세한 내용은 Study 글 "Owl BLE 본딩과 동기화 프로토콜"에 따로 적었다.

### Android 앱

- CompanionDeviceManager로 기기를 등록하고, 앱을 열지 않아도 15분마다 자동 동기화한다.
- 타임라인: [시각 · 장소 · 텍스트]를 시간순으로 보여준다. 간격 2분 이하로 이어진 녹음은 하나의 기록으로 묶는다. 세그먼트가 최대 5분이라 하나씩 보여주면 대화가 잘게 잘리기 때문이다.
- 장소 이름은 사용자가 붙인다. 네트워크 지오코딩은 위치가 폰 밖으로 나가서 쓰지 않았고, 오프라인 지명 데이터는 앱 용량이 수십 MB 늘어서 뺐다. 붙인 이름은 반경 100m 안의 기록에 자동 적용된다.
- 녹음이 빈 이유(녹음 꺼짐, 저장 공간 가득, 배터리 부족, 기기 꺼짐)를 타임라인에 약한 한 줄로 보여준다.
- 음성 보관 기간 선택, 북마크 필터, 검색, 테마(기본 다크), 앱 사용 기록과 집계 탭(장소별 머문 시간, 앱별 사용 시간)도 들어갔다.
- 온디바이스 STT는 인터페이스만 있고 엔진은 아직 정하지 않았다(whisper.cpp 또는 sherpa-onnx 후보).

![Owl 앱 화면: 타임라인, 기록 상세, 기기](/images/posts/owl/app-screens.png)
*그림. 왼쪽부터 타임라인, 기록 상세(합친 기록 재생), 기기 화면. 에뮬레이터에서 가짜 목걸이의 시험 데이터로 찍었다.*

### 하드웨어 없이 검증하기

보드가 오기 전에 대부분을 구현해야 해서 검증 도구를 먼저 만들었다.

- `tools/owlproto.py`와 테스트가 프로토콜 문서의 숫자를 검증한다.
- 펌웨어는 `native_sim`에서 테스트를 돌린다.
- Android 에뮬레이터의 가상 블루투스에 **Google Bumble로 만든 가짜 목걸이**를 붙여, 앱의 진짜 BLE 경로(CDM 등록·본딩·동기화·이어받기·UNPAIR)를 코드 수정 없이 시험했다.
- 가짜 목걸이에 일주일 치 데이터를 부팅별로 재생해 QA를 하고, 나온 문제를 결정 기록과 함께 고쳤다.

### 케이스

OpenSCAD로 케이스를 코드로 만들었다. 부품 실측값만 바꾸면 다시 만들 수 있고, 부품이 뚜껑·모서리에 닿으면 `assert`가 알려준다. 목표 크기는 고리를 빼고 약 36 × 24 × 13mm다. 예비 방법으로 3D펜 도면도 만들었다.

![OpenSCAD 케이스 분해 렌더: 뚜껑, 보드와 배선, 몸통](/images/posts/owl/case-exploded.png)
*그림. OpenSCAD 모델의 분해 렌더. 위에서부터 뚜껑, 보드·배선·버튼, 몸통이다.*

## 서브 프로젝트: owl_laya (상황 분류)

타임라인 기록마다 "그때 어떤 상황이었나"를 **독백 · 일상 대화 · 강의 · 일** 중 하나로 붙이는 온디바이스 분류 모델이다. 결정 모델 Laya(다국어 322M)를 한국어로 파인튜닝해 폰에서 돌리는 설계다. 아직 설계 초안 단계이고 코드는 없다. Owl PRD에도 아직 없는 기능이다.

설계 내용은 Study 글 "온디바이스 상황 분류기 설계"에 따로 적었다.

## 현재 상태

- 하드웨어 없이 할 수 있는 M0–M4(bring-up, 녹음, Opus+VAD, BLE, 앱) 구현이 들어왔고, 보드 검증을 기다리는 단계다.
- 2026.11.07 기준, 실제 XIAO nRF54L15 Sense에 bring-up 앱을 구워 마이크 값을 확인하기 시작했다.
- 남은 것: 보드에서 녹음·VAD 임계값·Opus 인코딩 시간·BLE 처리량 확인, 실측 소비전류(M5), STT 엔진 선택(M6), 케이스 출력과 하루 착용 테스트(M7).
- 배터리 수명 목표는 한 번 충전으로 16시간 이상이다. 문서의 추정치는 2–5일이지만 아직 실측 전이다.
