> 임시 게시글: GitHub 기록을 바탕으로 작성한 초안이며, 이후 다듬을 예정이다.

> [PolyGraphics](https://github.com/wndgur2/PolyGraphics)를 만들면서 정리한 내용이다. 게임 그림을 코드가 아니라 데이터로 두면 무엇이 가능해지는지, 그리고 그걸 지키려면 렌더러가 무엇을 보장해야 하는지를 다룬다.

## 1. 문제: 그림이 그리기 코드로만 존재할 때

도형 아트 게임 두 개를 감사해 보니 그림은 전부 명령형 코드였다. `Graphics`에 원과 다각형을 차례로 그려 텍스처로 굽거나, `_ready()`에서 노드를 조립하는 식이다.

이 방식에서는 에셋 하나를 **찾을 수도, 비교할 수도, 검증할 수도** 없다.

- 적의 생김새는 부트 코드 속 이름 없는 블록이다. 데이터만 추가하면 텍스처 없는 상자가 나온다.
- 색은 리터럴로 흩어진다. 한 게임은 강조색 하나를 바꾸려면 22곳을 고쳐야 했고, 다른 게임에는 `ff9b3d`와 `ff9d3c`처럼 의도치 않게 갈라진 색이 있었다.
- 그릴 때 난수를 쓰면 같은 화면도 매번 다르게 나온다. 스크린샷 diff가 의미가 없어진다.

AI 에이전트 입장에서는 더 심각하다. 생성 → 확인 → 수정 루프를 돌려야 하는데, 에셋 하나를 따로 렌더링할 방법이 없으면 루프 자체가 불가능하다.

## 2. 에셋 = 선언형 JSON 문서

PolyGraphics에서 에셋은 렌더러가 해석하는 문서다.

```jsonc
{
  "id": "demo.enemy.imp",
  "description": "Small aggressive melee chaser: …",   // 필수
  "tags": ["enemy", "melee", "small"],
  "size": [32, 32],
  "parts": [ … ],                // 이름 붙은 파트, 배열 순서 = 그리는 순서
  "variants": { "elite": … },    // 선언형 패치
  "animations": { "idle": … }    // 파트별 키프레임
}
```

- **파트에는 id가 있다.** variant와 animation이 id로 파트를 가리킨다. `rect3`이 아니라 `pauldron`처럼 이름 짓는 게 규칙이다.
- **variant는 다시 그리기가 아니라 패치다.** `set` / `add` / `remove`로 원본을 고치고, 패치된 파트는 다시 검증한다. 기존 게임의 variant가 "크기 × 색조"뿐이던 것을 실제 상태 변화로 바꿀 수 있다.
- **`use`로 합성한다.** 무기 아이콘이 투사체 문서를 그대로 품으니, 아이콘과 실제 투사체가 어긋날 수 없다.

문서이기 때문에 git diff가 곧 디자인 변경 내역이 된다.

## 3. Design token: 값 대신 참조

칠하는 값은 전부 토큰 참조다.

```
"$blood"          colors.blood
"$blood.light"    ramps.light만큼 밝게 (.light2 / .dark / .dark2)
"$blood@soft"     alpha 토큰의 투명도
```

선 굵기(`"width": "thin"`)와 투명도도 토큰 이름을 받는다. 토큰은 두 층이다. `tokens/base.json`은 모든 앱이 공유하는 "물리량"(램프, 선 굵기, 알파, 회색)이고, 앱의 `tokens.json`이 그 위에 팔레트를 얹는다.

**theme은 토큰 오버레이일 뿐이다.** `themes/ice.json`이 따뜻한 색을 차가운 색으로 바꾸면 로스터 전체가 한 번에 바뀌고, 실루엣은 건드리지 않는다. 기존 게임에서는 수백 곳 찾아 바꾸기였던 일이다.

## 4. 결정적 렌더링

렌더러 헤더에 계약이 적혀 있다. **같은 에셋 + 같은 토큰 + 같은 seed → 바이트 단위로 같은 SVG.** 이를 위해 지키는 것들이다.

- **난수는 seed가 있는 PRNG만 쓴다.** `repeat` 파트(자갈, 반점 같은 scatter)는 mulberry32를 쓰고, seed를 안 적으면 `"<에셋id>:<파트id>"` 문자열의 해시에서 seed를 만든다. 다른 곳에서 무작위성을 만들지 말라는 것이 에이전트 규칙에도 들어 있다.
- **벽시계를 쓰지 않는다.** 시간에 따라 달라지는 값이 출력에 섞이지 않는다.
- **숫자 출력을 고정한다.** 좌표는 소수 둘째 자리로 반올림하고, `-0`은 `0`으로 바꿔 쓴다. 같은 값이 다른 문자열로 찍히는 경우를 없앤다.

사운드도 같은 규칙을 따른다. 무작위성은 전부 IR에 실린 seed PRNG라서 WAV bake도 매번 같다.

## 5. 왜 결정성이 diff와 회귀 테스트를 가능하게 하나

출력이 매번 같으면 **출력이 바뀌었다는 것 자체가 정보**가 된다.

```bash
npm run baseline   # 현재 bake를 기준으로 승인 (apps/<id>/baselines/ 커밋)
npm run regress    # 현재 PNG·WAV를 baseline과 바이트 비교, 바뀌면 exit 1
```

- 토큰 한 자리가 바뀌면(`ff9b3d` → `ff9d3c`류의 실수) 그 토큰을 쓰는 에셋만 정확히 실패한다.
- 리팩터링은 "baseline 그대로"를 불변식으로 삼을 수 있다. 사운드 컴파일러를 크게 고칠 때도 단계마다 "28/28 unchanged" 같은 조건을 걸고 진행했다.
- 반대로 일부러 바꾼 커밋은 어떤 baseline이 다시 승인됐는지로 범위가 드러난다.

반올림 순서 하나 바꾼 것도 잡힌다. 사운드 컴파일러가 pitch·stretch 스케일을 결과 위에 덧곱하던 방식을 재귀 안으로 내리면서 값을 두 번이 아니라 한 번만 반올림하게 되자, 한 문서의 노이즈 grain 세 개가 최대 0.1ms 움직여 바이트 diff가 났다. 문서는 이를 조용히 다시 승인하지 않고, 왜 바뀌었는지 기록으로 남겼다.

## 6. 제안이 붙는 lint

`npm run check`는 통과하거나, 정확히 무엇을 고칠지 말해준다.

- 모르는 토큰은 에러이고, Levenshtein 거리로 가까운 후보 3개를 붙인다. (`unknown color token $bloood — did you mean $blood?`)
- raw `#hex`는 렌더링은 되지만 가장 가까운 토큰을 알려주며 경고한다. 사운드의 raw Hz도 똑같다.
- 아무도 안 쓰는 색 토큰은 dead로 보고하고, theme이 없는 토큰을 덮어쓰면 조용히 무시하지 않고 에러를 낸다.

앱마다 규칙도 매니페스트(`app.json`)에 적는다. 4px 그리드, 32×32 크기, 모든 적 몸체에 `death` clip, 무기 아이콘끼리 ΔE2000 13 이상, 게임 코드가 나눗셈에 쓰는 반지름 같은 geometry contract(이건 에러) 등이다. 규칙을 일부러 벗어날 때는 문서에 `"why": { "size": "…" }`를 적는다. 그러면 예외가 "모두가 스크롤해 넘기는 경고"가 아니라 "누군가 내린 결정"으로 남는다.

## 7. 컴파일된 IR과 엔진 어댑터

엔진은 문서를 직접 읽지 않고 컴파일된 IR을 받는다. IR에서는 토큰이 `[r,g,b,a]` float으로 풀려 있고, variant가 적용돼 있고, `use`가 인라인돼 있고, `repeat`와 `mirrorX`가 전개돼 있다. 그래서 **어댑터는 단순한 해석기**이고 토큰·문법·PRNG 로직은 게임에 실리지 않는다.

- **Phaser** (`polygraphics-phaser.ts` 파일 하나): `bakeFlat`(텍스처 하나), `buildRig`(파트별 Image + 키프레임 재생), `drawAsset`(크기가 런타임에 정해지는 이펙트를 매 프레임 지오메트리로 다시 그림)
- **Godot** (`polygraphics.gd` 파일 하나): `build`로 Node2D 트리, `play`로 Tween

게임의 렌더 파이프라인은 그대로다. 바뀌는 건 에셋을 만드는 한 지점뿐이다.

어댑터가 여럿이면 "갤러리에서 본 것 = 게임에서 보이는 것"을 지키는 게 일이 된다. 실제로 렌더러는 외곽선을 fill 아래에 깔아(`paint-order: stroke`) 바깥 절반만 보이게 하는데, 두 어댑터는 fill 위에 그리고 있어서 게임 안 외곽선이 갤러리의 두 배였다. 몇 px짜리 다리나 더듬이는 그게 거의 전부라서, 갤러리에서는 밝던 꼬리가 게임에서는 검게 나왔다. 같은 이유로 clip을 읽는 코드는 `src/anim.ts` 한 곳에 두고, Phaser 어댑터가 가진 복사본과 같은 값을 내는지 `scripts/test-anim.ts`가 라이브러리의 모든 트랙을 샘플링해 비교한다.

## 8. 정리

- 그림을 데이터로 두면 diff, 패치, 검증, 단독 렌더링이 전부 공짜로 따라온다.
- design token은 색을 "값"에서 "의미"로 옮긴다. 테마 변경과 색 드리프트 탐지가 같은 장치로 된다.
- 결정적 렌더링은 회귀 테스트의 전제다. 난수는 seed로, 숫자는 고정 포맷으로, 시계는 쓰지 않는다.
- lint는 에러를 내는 것보다 **고칠 방법을 말해주는 것**이 중요하다. 작성자가 AI일 때 특히 그렇다.
- 구조·일관성·비회귀는 기계가 보장하고, 취향은 눈과 귀가 있는 사람에게 남긴다.
