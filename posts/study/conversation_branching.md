> 임시 게시글: 작업 기록을 바탕으로 작성한 초안이며, 이후 다듬을 예정이다.

> 업무에서 LLM 에이전트 채팅에 "이 지점에서 새 대화로 갈래 만들기" 기능을 넣었다.
> 기능 자체는 작지만, 대화 기록이 두 층에 나뉘어 있어서 생각할 것이 있었다.

## 1. 왜 필요했나

앞쪽 질문을 편집해 다시 보내거나 답변을 재생성하면 **그 지점 뒤의 메시지가 지워졌다.** 원래 흐름을 남긴 채 다른 방향을 시도하려면 새 대화를 열고 맥락을 다시 입력해야 했다.

원하는 동작은 단순하다. 선택한 답변까지를 새 대화로 복사하고, 원본은 건드리지 않는다.

## 2. 복사해야 할 것이 두 층이다

- **앱의 대화 기록**: 화면에 보이는 메시지, 첨부, 도구 실행 카드
- **에이전트 세션의 기억**: 모델이 다음 턴에 실제로 보는 문맥. 텍스트뿐 아니라 도구 호출·결과, 파일 참조까지

앱 메시지만 복사하면 화면은 같아 보여도 모델은 아무것도 기억하지 못한다. 그래서 세션 레이어에 **fork API**를 따로 만들었다.

## 3. 세션 fork API

`POST /sessions/{id}/fork { turnId }` → 새 세션. 모델을 실행하거나 새 턴을 시작하지는 않는다.

- **완료된 턴까지만** 받는다. 진행 중인 턴을 지정하면 아무것도 쓰지 않고 409를 돌려준다. 절반만 끝난 도구 호출을 복사하면 이어 갈 수 없는 상태가 된다.
- 복사한 턴·응답·출력에는 새 ID를 발급하되, **정해진 참조 필드만** 다시 쓴다. 본문이나 도구 결과 안에 원본 ID 문자열이 들어 있어도 그 값은 건드리지 않는다. 사용자 데이터를 "똑똑하게" 치환하면 원문이 바뀐다.
- 파일 객체는 원본과 공유하고, 첨부가 몇 번, 어떤 타입으로, 어떤 순서로 붙었는지는 그대로 복사한다.
- 사용량·과금·모니터링 기록은 복사하지 않는다. 복사본이 사용량을 두 번 세면 안 된다.
- 원본 세션을 잠근 채 한 트랜잭션에서 복사한다. 분기점 이후 기록은 제외한다.
- 권한은 원본에서 "다음 턴을 실행할 수 있는가"와 같은 수준을 요구한다. fork한 사람에게는 새 세션의 실행 역할만 주고, 원본의 다른 역할 배정은 복사하지 않는다.

## 4. 앱 쪽 순서와 보상

```
1. 자를 답변이 완료된 세션 턴을 갖고 있는지 확인 (없으면 409, 아무것도 안 함)
2. 앱 DB에서 메시지 행 복사 (한 트랜잭션)
3. 세션 fork
4. 새 대화에 fork된 세션 id 기록
```

두 시스템에 걸친 작업이라 중간 실패를 되돌리는 경로를 정해 뒀다.

- 3이 실패하면 2에서 만든 대화를 지운다. **기억 없이 시작하는 갈래**를 남기지 않는다.
- 4가 실패하면 3의 fork 세션을 지운다. 목록에 고아 세션이 남지 않게.

버튼은 "세션 턴이 완료된 답변"에서만 보여야 한다. 그래서 턴 완료 이벤트를 받는 시점에 답변 메시지에 세션 턴 id를 같이 저장했다. 최종 저장 응답에 그 값이 실려 오므로, 답변이 끝나자마자 버튼이 뜬다.

## 5. 질문 버블에서도 갈래

처음엔 답변에만 버튼을 뒀는데, "질문을 바꿔 다시 물어보고 싶다"가 더 흔한 요구였다.

- 질문 버블에서 누르면 **바로 위 답변까지** 복사하고, 그 질문을 새 대화의 **입력창에 채운다.** 원본은 그대로 두고 질문만 고쳐 다시 보낼 수 있다.
- 바로 위 답변이 있어야 하므로 첫 질문에는 버튼이 없다.
- 서버는 바꾸지 않았다. 클라이언트가 "바로 위 답변"을 찾아 같은 API를 부른다.
- 채울 질문은 `sessionStorage`로 한 번만 넘기고, 새 화면이 마운트된 뒤 지운다. 새로고침했을 때 다시 채우지 않게.

## 6. UI 상태

- 누르면 서버가 복사·fork하고 목록을 갱신한 뒤 이동한다. 처음엔 버튼이 비활성화만 돼서 눌렸는지 알기 어려웠다. 대기 중에는 아이콘을 스피너로 바꿨다.
- 실패하면 원래 화면에 남고, 아이콘을 되돌리고, 에러 토스트를 띄운다.

## 7. flag 뒤에서 열기까지

처음엔 feature flag 뒤에 두고 내부 사용자에게만 열었다. 직접 써 보며 질문 버블 갈래, 스피너가 이 단계에서 추가됐다.

flag를 걷을 때 한 것:

- 클라이언트의 flag 게이트를 지우되, **노출 조건(완료된 세션 턴이 있는 답변만)은 그대로** 둔다. flag와 노출 조건은 다른 것이다.
- 서버 라우트의 "flag off면 404" 분기도 지운다. 접근 권한 검사와 409는 유지한다.
- flag 정의, 기본값, 관련 테스트를 함께 지운다. 환경 DB에 남은 flag override 행은 마이그레이션 대신 운영에서 정리하기로 했다.

## 8. 남은 한계

- 질문 갈래는 말풍선의 텍스트만 채운다. 첨부 파일은 갈래에서 다시 붙여야 한다.
- 세션 기억이 없는 예전 대화에서는 갈래를 만들 수 없다.
